Solution architecture

An autonomous LLMOps distillation pipeline, operated by agents
Seven AWS Bedrock AgentCore harnesses run the full model-distillation lifecycle — a teacher (DeepSeek-R1 on Bedrock) generates verified training data, a student (Qwen3-1.7B) is fine-tuned with QLoRA on SageMaker, evaluated against verifiable gates, deployed, and monitored. A Step Functions spine dispatches five stage workers; an orchestrator triages escalations before any human is paged; a FinOps auditor reconciles every dollar actually spent against the estimate that was approved. This console is the human control plane over that loop.

High-level · triggers → conductor → stage workers → AWS

loading diagram…
Four ways in (scheduler, GitHub Actions, admin API, webhook), one spine (start_pipeline → Step Functions → harness-driver), five stage workers, and the audit plane at the bottom: finops-daily fires the auditor every day at 09:00 UTC — it reads billing, reconciles, and cannot stop a run.

Low-level · inside a worker harness

loading diagram…
Each worker is a declarative AgentCore harness: Fable 5 in a microVM with shell + code interpreter, skills mounted from git, shared cross-run memory, and inline functions (stage_complete, checkpoint, job_launched, the finops audit tools) that the harness-driver Lambda services with a trust-but-verify contract — a claimed S3 artifact is head-checked before the call is accepted.

This console · how the dashboard itself is wired

loading diagram…
One Lambda serves this page and its API. GETs are public, read-only aggregations; every POST requires a Cognito token, and the $2,000 cost-approval gate is enforced server-side — the requester can never approve their own estimate.

How to read the diagrams

  • Colors are layers — purple: triggers · blue: orchestration spine · amber: agent harnesses · green: AWS services · red: human/ops surfaces.
  • Animated dashes show flow direction — the red loop on the high-level diagram is the self-remediation cycle: an eval gate failure re-dispatches finetune, at most 3 times, before escalating.
  • Every card is a link into the exact config or handler in the repository — the diagrams are generated from the live configs, not drawn aspirationally, and a layout test forbids crossing wires.
  • The audit plane is outside the state machine on purpose — reconciliation runs daily across many finished runs (Cost Explorer settles ~24h late), so it answers to the project, not to any single run, and its IAM is read-only on billing.
